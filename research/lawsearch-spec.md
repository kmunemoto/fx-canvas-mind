## 1. 期間・ペア・日付

- **ペア**: USD/JPY・EUR/JPY・AUD/JPY・EUR/USD・AUD/USD の5つだけ。pip は円のペア 0.01、ドルのペア 0.0001。
- **日付**（固定。この後変えない）:
  - S0 ＝ 2023-10-27 00:00 UTC。すべての指標と状態を、S0 からの足で途切れずに計算し始める。前半・後半で計算し直さない。
  - START ＝ 2024-01-01 00:00 UTC。
  - SPLIT ＝ 2025-05-19 00:00 UTC（月曜。tf-winrate・§8.106・§8.109・§8.111・§8.113 と同じ日。この研究の数字を見て決めた日ではない）。

- **半分**（T は合図の足の確定。X ＝ T ＋ N × 足の長さ は予定の出口の時刻）:

- **値段の元**:

- **計算の場所**: GMO はこの開発環境から届かないので、GitHub Actions で取る。日のファイルは actions/cache に置き、件数と sha256 を記録する。

## 2. 足の作り

- **読み込み**: `research/trend-data.ts` の `loadTf`。
  - 15分足（15min）と1時間足（1hour）の日のファイル、Bid と Ask の両方を読む。
  - 読む範囲は [fromMs, toMs)。始まり t が t ≧ fromMs で、t ＋ 長さ ≦ toMs の足だけを使う。
  - 読むファイルは `loadTf` と同じ（keysOf）: jstDayKey(t) ＝ (t ＋ 9時間) の UTC の日付として、jstDayKey(fromMs − 1日) から jstDayKey(toMs) までの毎日のファイル。古い順に読む。Python も、同じファイルを同じ順に読む。
  - ファイルの形（`parseKlines` と `readFile` を読んで書いた。21.5）:
    - 日のファイルは、1つの JSON の object。形は {"status": 0, "data": [{"openTime": "1735689600000", "open": "150.102", "high": "150.120", "low": "150.090", "close": "150.110"}, …]}。
    - 上の2つのほかの名前は、値の読み方には使わない。
    - 文字の行・見出しの行・行の終わりの文字は無い。区切りの文字で値を分けることもしない。
    - この決まりの「行」は、data の要素の1つ（1本の足の、始まりの時刻と四本値）。「ファイルの中の行の順」は、data の並びの順。
    - 使う名前は、openTime（始まりの時刻。UTC のミリ秒）と open・high・low・close（四本値）の5つだけ。ほかの名前は見ない。
    - JSON として読めないファイルと、「status が 0 か 404 で、data が配列」の形でないファイルは、読み込みの失敗とする（`ownerhold-data.ts` の sound。TS の loadTf は、取り直せる時は取り直してから決める）。
      - JSON は、JS の JSON.parse と同じに読む。NaN・Infinity の語は、JSON の値として受け付けない（Python の json は、そのままでは受け付けるので、断る）。
      - JSON の数は、その字に最も近い double とする（大きすぎれば無限。JSON.parse と同じ）。
  - `parseKlines` の作り（TS が使う。Python は読まないので、ここに書く）:
    - data を前から順に見る。要素が object でなければ、飛ばす。
    - object なら、5つの名前の値を数にする。JSON の数はそのまま、JSON の文字は JS の Number()、それ以外（null・true・false・無い名前など）は NaN。
    - 5つのどれかが有限でなければ、その行を落とす。
    - 残った行を openTime の順に並べ替える。同じ openTime の行どうしの順は変えない。
  - 値の読み方（21.5）:
    - openTime は、JSON の文字で、0〜9 の数字が1つ以上だけでできた形の時だけ、数にする。
    - open・high・low・close は、JSON の文字で、小数の形（0〜9 の数字が1つ以上と、多くて1つの小数点「.」だけでできた文字。例: "150.102"）の時だけ、数にする。
    - 数は、その文字に最も近い double（TS は Number()、Python は float()）。数にして有限でなければ（桁が多すぎる時）、parseKlines と同じく、その行を落とし、「数にできない行」として数える。
    - 形の違う値がある行は、その値がどれも parseKlines の作りで有限の数にならない時、落として「数にできない行」として数える。読み込みの失敗には数えない。例: "-"・"157_360"・"157.360.1"・"Infinity"・null・true・無い名前。
    - data の要素が object でない時（null・文字・数・配列）も、落として「数にできない行」として数える。
    - 形の違う値で、parseKlines の作りで有限の数になる値が1つでもあれば、止まる。TS と Python で読みが分かれうるため。
      - 値ごとに見る。同じ行に、落とす値（"-" など）があっても止まる。
      - 例: 空の文字 ""、空白 " "、16進 "0x10"、指数 "1e2"、符号 "+150.1"・"-150.1"、文字でない JSON の数（150.102 や、openTime の 1735689600000）、openTime の "1735689600000.0"。
    - 落とした行は、無い行とする。捨てた数・同じ始まりの行の数・15 の Ask < Bid の行の数には入れない。mergeSides の「最後の行」にも使わない（A.1.36 の b9）。
    - 数にできない行の数は、Bid と Ask の両方のファイルの行で数える。
    - Python では、JSON の true・false を数として扱わない（Python の bool は int の仲間なので、気をつける）。
    - GMO のファイルに、形の違う値があるかは確かめていない。
  - 2 の数（捨てた数、同じ始まりの行の数、数にできない行の数）は、`loadTf` を呼ぶ1回（ペア・足の長さ・fromMs・toMs）ごとに出す。読む範囲の外の行（前の1日のファイルの行、toMs より後の行）も入る。
  - 段1（toMs ＝ SPLIT）は、jstDayKey(SPLIT) のファイルにある SPLIT 以後の行も読む。その行は足にせず、2 の数にだけ入る。10 の「後半の足はメモリに載せない」と h1Only は、作った足で見る。
- **Bid と Ask を合わせる**（`mergeSides`）:
  - 同じ始まりの Bid と Ask の両方がある足だけを使う。
  - 行の順は `loadTf` の並べ方: 日のファイルの古い順、1つのファイルの中は行の順。始まりの順に並べ替えるが、同じ始まりの行どうしの順は変えない。
  - Ask に同じ始まりの行が2つ以上あれば、最後の行を使う（`mergeSides` は Ask を始まりで引く表にし、後の行が前の行を上書きする）。
  - Bid は前から順に見る。その始まりの足がまだ無く、同じ始まりの Ask があり、Ask の終値 ≧ Bid の終値 の行で、足を作る。
  - Ask の終値 < Bid の終値 の Bid の行は、捨てて数える。同じ始まりの次の Bid の行があれば、それを見る（使われうる）。
  - その始まりの足ができた後の Bid の行は、使わない。
  - 捨てた数は `loadTf` の数え方: 読んだファイルの Bid の行ごとに、同じ始まりの Ask（最後の行）の終値 < その行の終値 なら1と数える。読む範囲と週末の足で落とす前に数え、足ができた後の行も数える。
  - 同じ始まりの行の数（`loadTf` の数え方）: 前に同じ始まりの Bid の行がある Bid の行を、1と数える（同じファイルの中も含む）。
- **週末の足は捨てる**（`barInsideClosure`。§8.106 の WEEKEND＝inside）:
  - 始まり s と、s ＋ 長さ − 1ミリ秒の両方が `isMarketClosed` の中にある足を捨てる。
  - `isMarketClosed(t)`: UTC で、土曜は終日、金曜は 22:00 以後、日曜は 21:00 より前。
- **中値**:
  - 四本値ごとに、(Bid ＋ Ask) ÷ 2 を double で出す。
  - その double の正確な値を、小数 d 桁に丸める。ちょうど半分なら上へ。d は円のペア3、ドルのペア5。
  - TS は `Number(v.toFixed(d))`（チャートの historyRead と同じ）。
  - Python は `Decimal(v)`（float をそのまま）を `ROUND_HALF_UP` で丸める。`round`・`Decimal(str(v))`・10進の文字列での足し算は使わない。
  - 例: Bid 150.100・Ask 150.105 → double では 150.10249999999999204… → 150.102。
- **点**（整数。1点 ＝ 0.1 pip）:
  - 丸めた中値を、円のペアは1,000倍、ほかは100,000倍し、最も近い整数にする。TS は `Math.round`、Python は `round`。切り捨ては使わない。
  - Bid・Ask の生の値も同じ倍率で点にする。GMO の刻みは0.1 pip なので、整数から 1e−6 より離れたら止まる。
  - 中値の四本値の点を Po・Ph・Pl・Pc、Bid は Bo・Bh・Bl・Bc、Ask は Ao・Ah・Al・Ac と書く。
- **番号**:
  - ペアごと、足の長さごとに、S0 以後の最初の使える足を番号0とし、使える足に時刻の順に 0,1,2,… と付ける。
  - 無い足は詰める。前の番号の足を「1本前」とする。週末・穴・休みをまたいでも続ける。
- **記号**: 足 i の始まりを s_i、確定を T_i ＝ s_i ＋ STEP とする。STEP は15分足 900,000ミリ秒、1時間足 3,600,000ミリ秒。O・H・L・C は丸めた中値（double）。
- **上位足**:
  - 15分足の試しには1時間足、1時間足の試しには4時間足を使う。
  - どちらも、その試しの元の足から、GMO の格子でまとめて作る（`coarsen`。始まり ＝ floor(t ÷ 長さ) × 長さ）。始値は最初の足、終値は最後の足、高値・安値は中の足の最大・最小。Bid と Ask をそれぞれまとめてから、中値を作る（中値の作りは上と同じ）。
  - GMO の4時間足のファイルは使わない。
  - 上位足の番号も、S0 からの通しにする。
  - 上位足の k 本目を足 i の判断に使ってよいのは、その格子の終わり（始まり ＋ 上位足の長さ）≦ T_i の時だけ。元の足に穴があっても、時計で決める。
- **日**（F07・E30 に使う）:
  - 日 D(t) は、(t ＋ 3時間) の UTC の日付（`gmoDayKey` と同じ。21:00 UTC 区切り）。
  - ただし D(t) が土曜なら、その前の金曜にする（冬の金曜 21:00〜22:00 UTC の切れ端を、金曜の日に入れる。反証 C8）。
  - 足 i の日は D(s_i)。
- **季節**:
  - NY の夏時間は `nyOffsetMs` と同じ（その UTC の年の3月第2日曜 07:00 UTC 以上、11月第1日曜 06:00 UTC 未満が UTC−4。07:00 ちょうどは夏、06:00 ちょうどは冬）。

## 3. 計算の作り（指標の式の表）

### 3.1 共通の決まり

- **無し**: 値が計算できない（温めの前、分母が0など）ことを「無し」と書く。
- **浮動小数**:
  - 和は、古い方から1つずつ足す。
  - 標準偏差は2回に分けて計算する（先に平均、次に (値 − 平均)² を古い方から足す）。
  - 式の中の計算の順は、書いたとおりにする（例: `100 * a / b` は (100×a)÷b）。
  - 2乗は x*x で計算する。
  - 8.5 の「|x| < 1e−12 を 0 とする」は、8 の数（Δ・SE・t・p など）だけに当てる。
  - 指標・交差・F の比べには、幅を置かない。決めた型のまま比べる（double は double、点は整数）。丸めだけで出る小さな差（1e−12 より小さくても）も、そのまま比べる（21.5）。
  - Python は `sum`・`fsum`・`np.sum`・`np.mean`・`np.std`・`np.convolve`・pandas の rolling を使わない（足す順が違い、最後の桁が変わりうる。反証 C5）。
- **交差**（4つの値がすべてある時だけ。比べは double のまま。等しい時は越えていない）:
  - X↑(a, b): a[i−1] ≦ b[i−1] かつ a[i] > b[i]。
  - X↓(a, b): a[i−1] ≧ b[i−1] かつ a[i] < b[i]。
  - b が定数 L の時も同じ（例: X↑(RSI, 30) は RSI[i−1] ≦ 30 かつ RSI[i] > 30。ULTRA と同じ形）。
- **ローソク足の比べ**: 実体・ヒゲ・値幅の大きさの比べは、すべて点（整数）で行う。
  - 3.2 の式を丸めた中値（double）で書いた指標（TR・ATR など）は、これに入らない。double で計算し、double で比べる（例: E32 の TR[i] ≧ 2×ATR14[i−1]。C > O も double のまま。丸めた中値の大小は、点の大小と同じ）。
  - CCI・ROC は、3.2 のとおり点で計算する。§8.113 から引く項目（E44 など）は、その項目の決まりの単位のまま（17.3）。

### 3.2 指標の式

TS は、17.1 の一覧のアプリの関数を呼ぶ（使う出力も 17.1）。一覧に無い式（SMA・ボリンジャー・ストキャス・CCI・ROC・アルーン、ケルトナーの組み立て、4.1 の E29〜E32・E43 の式、4.2 の F の組み立て〈SMA100(ATR14)・日の始値・上位足の EMA50 の差など〉）は、TS も研究の中に、下の式どおりに書く（式の中の EMA・ATR などは、一覧の関数で出す）。Python は下の式から書く。

**SMA_p(x)**
- i ≧ p−1 で、x[i−p+1..i] がすべてある時だけ計算する。
- (x[i−p+1] ＋ … ＋ x[i]) ÷ p。古い方から足してから、p で割る。
- 注意: `pine.ts` の `sma` は新しい方から足す。この研究では使わず、研究の中に古い方から足す SMA を書く。

**EMA_p・RMA_p**（`pine.ts` の pineEma・pineRma）
- α は、EMA が 2÷(p+1)、RMA が 1÷p（double で1回割る）。
- 1−α は、その double の α を 1 から引いた値（(p−1)÷(p+1) などで作り直さない。`pine.ts` と同じ）。
- 種（prev が無しの間）:
  - i ≧ p−1 で、x[i−p+1..i] がすべてある最初の i で、prev ＝（古い方から足した和）÷ p。out[i] ＝ prev。
- その後:
  - x[i] があれば、prev ＝ α×x[i] ＋ (1−α)×prev（この順に計算する）。out[i] ＝ prev。
  - x[i] が無しなら、prev ＝ 無し、out[i] ＝ 無し。次に p 個そろった所で、種から取り直す。
  - 有限でない値（NaN・±∞）も無しとする。種の窓でも同じ（`pine.ts` と同じ）。

**ATR_p**（`pine.ts` の pineAtr）
- TR[0] ＝ H[0] − L[0]。
- i ≧ 1 は、TR[i] ＝ max(H[i]−L[i], |H[i]−C[i−1]|, |L[i]−C[i−1]|)。C[i−1] は番号で1つ前の足で、空きをまたいでもそのまま使う。
- i < p−1 は無し。ATR[p−1] ＝ (TR[0]＋…＋TR[p−1]) ÷ p。
- i ≧ p は、ATR[i] ＝ (TR[i] ＋ (p−1)×ATR[i−1]) ÷ p（RMA と式の形が違う。この形を使う）。

**RSI_p**（`ultra.ts` の pineRsi）
- up[0] と dn[0] は無し。
- i ≧ 1 は、up[i] ＝ max(C[i]−C[i−1], 0)、dn[i] ＝ max(C[i−1]−C[i], 0)。
- U ＝ RMA_p(up)、D ＝ RMA_p(dn)。最初の値は i ＝ p。
- RSI の値:
  - どちらかが無しなら、無し。
  - D ＝ 0 なら 100。
  - そうでなく U ＝ 0 なら 0。
  - それ以外は 100 − 100 ÷ (1 ＋ U÷D)。

**MACD(f, s, m)**（`_shared/macd.ts` の macd）
- 線 ＝ EMA_f(C) − EMA_s(C)。どちらかが無しなら無し。
- シグナル ＝ EMA_m(線)。種は、線が m 個そろう最初の足（i ＝ s+m−2）。

**ボリンジャー(20, k)**
- 中心 m ＝ SMA20(C)。
- sd ＝ √(ss ÷ 20)。ss は (C[j] − m)×(C[j] − m) を j ＝ i−19 から i まで古い方から足した和。足してから20で割る（1つずつ割らない）。m は足 i の SMA20。
- 上 ＝ m ＋ k×sd、下 ＝ m − k×sd（k×sd を先に計算する）。
- 帯の幅 w ＝ 上 − 下。

**ストキャスティクス・スロー(k, 3, 3)**
- HH ＝ max H[i−k+1..i]、LL ＝ min L[i−k+1..i]。
- rawK ＝ 100×(C−LL) ÷ (HH−LL)。HH ＝ LL なら無し。
- %K ＝ SMA3(rawK)、%D ＝ SMA3(%K)（無しを含む窓は無し）。

**CCI(20)**（点の整数で計算する。§8.113 C15 と同じ作り）
- Tp[k] ＝ Ph[k] ＋ Pl[k] ＋ Pc[k]。
- S[i] ＝ Tp[i−19..i] の和。
- x[i] ＝ 20×Tp[i] − S[i]。
- Dv[i] ＝ Σ_{k=i−19..i} |20×Tp[k] − S[i]|。
- Dv ＝ 0 か i < 19 なら無し。
- 比べは割らずに整数で行う:
  - CCI > +100 ⇔ 40x > 3Dv
  - CCI ≦ +100 ⇔ 40x ≦ 3Dv
  - CCI < −100 ⇔ 40x < −3Dv
  - CCI ≧ −100 ⇔ 40x ≧ −3Dv

**ROC(12)**: q[i] ＝ Pc[i] − Pc[i−12]（点）。

**DMI・ADX(14, 14)**（`trendTools.ts` の dmi）
- i ≧ 1 で、up ＝ H[i]−H[i−1]、dw ＝ L[i−1]−L[i]。
  - +DM ＝ up（up > dw かつ up > 0 の時）、でなければ 0。
  - −DM ＝ dw（dw > up かつ dw > 0 の時）、でなければ 0。
  - TR は ATR と同じ式。
- 番号0の +DM・−DM・TR は無し。
- trur ＝ RMA14(TR)、p ＝ RMA14(+DM)、q ＝ RMA14(−DM)。
- +DI ＝ fixnan(100×p ÷ trur)、−DI ＝ fixnan(100×q ÷ trur)。
  - fixnan: 値が無しか有限でない時（trur ＝ 0 の時など）は、前の有限の値。まだ無ければ無し。
- dx ＝ |+DI − −DI| ÷ s。s ＝ +DI ＋ −DI で、s ＝ 0 なら 1 で割る。+DI か −DI が無しなら、dx も無し（`dmi` と同じ）。
- ADX ＝ 100 × RMA14(dx)（RMA14 の各値に、後から 100 を掛ける。dx を先に 100 倍しない。`dmi` と同じ）。

**パラボリック SAR(0.02, 0.2)**（`analyze/rsisar.ts` の parabolicSar）
- 番号0から計算する（足が3本未満なら無し）。
- 始め:
  - up ＝ (C[1] > C[0])。
  - s ＝ up なら L[0]、でなければ H[0]。
  - ep ＝ up なら H[1]、でなければ L[1]。
  - af ＝ 0.02。
  - long[1] ＝ up。
- i ≧ 2 ごとに、nx ＝ s ＋ af×(ep − s)。
- up の時:
  - nx ＝ min(nx, L[i−1], L[i−2])。
  - L[i] < nx なら、up ＝ 偽、nx ＝ ep、ep ＝ L[i]、af ＝ 0.02。
  - そうでなく H[i] > ep なら、ep ＝ H[i]、af ＝ min(af＋0.02, 0.2)。
- up でない時は、その鏡:
  - nx ＝ max(nx, H[i−1], H[i−2])。
  - H[i] > nx なら、up ＝ 真、nx ＝ ep、ep ＝ H[i]、af ＝ 0.02。
  - そうでなく L[i] < ep なら、ep ＝ L[i]、af ＝ min(af＋0.02, 0.2)。
- 最後に s ＝ nx、long[i] ＝ up。

**一目(9, 26, 52, ずらし26)**（`trendTools.ts` の ichimoku）
- 転換 ＝ (max H[i−8..i] ＋ min L[i−8..i]) ÷ 2。
- 基準 ＝ 26本で同じ。
- 先行1 ＝ (転換＋基準) ÷ 2。先行2 ＝ 52本で同じ。
- 足 i に描かれた雲:
  - A[i] ＝ 先行1[i−25]、B[i] ＝ 先行2[i−25]。
  - 上端 ＝ max(A, B)、下端 ＝ min(A, B)。

**RCI(9)**（`src/lib/rci.ts` の rci）
- TS は rci を length 9 で呼び、rci の列だけを使う（rci.ts の既定は length 10。ma は使わない）。
- 窓 C[i−8..i]。時刻の番号 t ＝ 0（古い）〜8。
- 各値の順位 ＝（窓の中でそれより小さい数）＋（等しい数 − 1）÷ 2。
- mr ＝ 順位の平均（古い方から足して9で割る）。
- num ＝ Σ (t−4)(順位−mr)、vt ＝ Σ(t−4)²、vr ＝ Σ(順位−mr)²（どれも t ＝ 0 から足す）。
- RCI ＝ 100×num ÷ √(vt×vr)。vr ＝ 0 なら無し。
- 注: TS の rci.ts は `** 2` を使う。Python は x*x。
  - 判断が分かれてよいのは、RCI[i] か RCI[i−1] が ±80 から 1e−9 未満の足の E12 だけ（交差は足 i−1 の値も使うため。17）。
  - 順位の和はいつも 36 なので mr はちょうど 4。順位 − mr は 0.5 の倍数、t − 4 は整数なので、2乗と num・vt・vr はちょうどの値になる（算数）。だから、`** 2` でも x*x でも同じ値になる見込み。Node 22（V8）では、300万個の double で `x ** 2` と x*x は同じ値だった（2026-11-04 に測った。Deno では測っていない）。

**スーパートレンド(10, 3)**（`src/lib/supertrend.ts` の supertrend）
- src ＝ (H＋L) ÷ 2、a ＝ ATR10。
- up ＝ src − 3a、dn ＝ src ＋ 3a（a が無しなら無し）。
- up1 ＝ 前の足の up。前の足で下の引き上げをした後の値（`supertrend.ts` と同じ）。前の足の up が無しなら、今の足の up。
- dn1 も同じ（前の足で引き下げをした後の dn。無しなら今の dn）。
- 帯の引き上げ・引き下げ:
  - i > 0 で、up と up1 があり、C[i−1] > up1 なら、up ＝ max(up, up1)。
  - i > 0 で、dn と dn1 があり、C[i−1] < dn1 なら、dn ＝ min(dn, dn1)。
- 向き tr（番号0は 1）:
  - 前が −1 で、dn1 があり、C[i] > dn1 なら 1。
  - 前が 1 で、up1 があり、C[i] < up1 なら −1。
  - それ以外は前のまま。
- 向きは a がある足でだけ「ある」とする。

**ケルトナー**: 中心 ＝ EMA20(C)。上 ＝ 中心 ＋ 2×ATR10、下 ＝ 中心 − 2×ATR10（2×ATR10 を先に計算する。TS は pineEma(C, 20) と、中値の double の pineAtr(10) を組む）。

**アルーン(25)**
- 窓は H[i−25..i]（26本）。最高値の番号 g は、同じ値なら新しい方。
- Up ＝ 100×(25 − (i−g)) ÷ 25。
- Down は L の最安値で同じ。
- i < 25 は無し。

- 向きを持つ条件そのものを、試しにしたもの。

## 5. 合図（出来事）の作り

- **判断に使えるもの**: 確定が T_i 以前の足の中値と、時計・暦だけ。
- **条件型**: 向き d ごとの条件が足 i で成り立ち、足 i−1 で成り立たない時だけ、合図にする（立ち上がり）。
  - E01〜E25・E28〜E36・E38・E39・E41・E43・E44 と、B の条件型の項目。
  - 交差の式の項目: 4.1 の式が X↑・X↓ を含む項目（E01〜E21・E24・E25・E28・E31・E35・E36・E38・E41）と、足 i−1 と足 i の2本で越え方を書いた項目（E22・E23・E33・E34）。
    - その式が真の足を合図とする。
    - この式は2本続けて真にならない（X↑ は、足 i−1 でまだ越えていないことを含む。E22・E23・E33・E34 の2本の式も同じ）。だから、立ち上がりは式に入っている。
    - 単なる X↑(a, b) は、状態「a > b」に、立ち上がりと下の「合図にしない足」の2つを当てた答えと同じになる。
    - 式の中の指標の値が1つでも無しなら、真にしない。その足は合図にならないが、次の足は止めない。
    - ただし E31 の「押しつぶしが i−5〜i−1 にある」は、4.1 の注のとおりに決める（窓の中で押しつぶしが無しの足は、真でない足として数える）。
    - 下の「合図にしない足」の2つは、この項目には重ねて当てない。だから、交差の値が初めてそろう足（温めの直後、ストキャスや RCI の無しが明けた直後）も、合図になりうる。
  - 式を状態に置き換えない。
    - 例: E36 の買いは、ADX が 25 を上に越えた足で、かつ +DI > −DI の時だけ。ADX が 25 より上のまま +DI が −DI を上に越えた足は、合図ではない。
    - X↑ にほかの式を「かつ」でつないだ E10・E11・E31 も同じ。
  - それ以外の条件型（E29・E30・E32・E39・E43・E44）は、書いた状態を条件とし、立ち上がりを見る。B の条件型の項目は、§8.113 で書いた条件と決まりのまま（17.3）。
- **常に持つ型**: 目標が d に変わった足を合図にする（0 から d へ、反対から d へ）。d から 0 に変わった足は、合図ではない。
  - E26・E27・E37・E40・E42 と、§8.113 で常に持つ型とした B の項目。
- **合図にしない足**:
  - 条件（向きごと）が S0 の後に初めて無しでなくなった足。
  - 足 i−1 の条件が無しの足。
  - §8.113 で「判断しない」とした足の条件は「成り立たない」とする（無しではない）。
- **決める順**:
  - ① 条件を出す。
  - ② 立ち上がりを見る（① の条件で見る。③〜⑤ で出さなかった足の条件も、次の足の「足 i−1 の条件」には ① のまま入れる。§8.113 5 と同じ）。
  - ③ 項目の残す決まり（1日1回、B06 の時刻の除外〈17.3〉など。§8.113 の置6）を当てる。
  - ④ F を当てる。
  - ⑤ 同じ試し・同じペア・同じ足に買いと売りの両方が残ったら、どちらも出さない（数を出す。数は合図で数え、1つの足で買いと売りの2件とする）。
- **S の行**: 立ち上がりを見ず、F(d) が真の足すべてが合図。向きを持つ F は、同じ足で両方の向きが真にならない。
  - 上の「合図にしない足」の2つ（初めて無しでなくなった足、足 i−1 の条件が無しの足）も、S の行には当てない。F の値がある足で F(d) が真なら、合図。
- **件数の数え方**: 1つの合図は（試し・ペア・向き・T）で1件。前の取引を持っている間に出ても、それぞれ1件と数える（§8.113 置5）。

## 6. 外す理由

- 次の順に当てて、最初に当たった1つの理由だけに数える。どれも、時計と T_i 以前の足だけで決まる（T より後の足の有無で外さない。§8.113 置7、反証 B1）。
- 成績を使わないので、段0で数える。①〜⑥を通った合図を「数えた合図」と呼ぶ。

**① 期間**
- T_i が、どちらの半分にも入らない（1）。
- 温めが足りない: 足の番号が、その試しの温めの本数 k より前（5 の表、F の温め、B は §8.113。番号 k 以上だけを残す。21.5）。
  - T が半分に入るのに、温めだけで外した合図の数を、① の中で分けて出す（見込みでは0。0でなければ、その試しと項目の名前も出す）。
- F の値が無い足は、4.2 の「F が無し」で数える（5 の④。6 より前）。① には入らない。
- ①b: 1 の「境で外すもの」（START ≦ T < SPLIT で、前半に入らない合図）。
  - ①b の数は ① の数に入れず、分けて出す。① の数は、残りの「どちらの半分にも入らない合図」と、温めが足りない合図。
  - ①b に当たる合図は、温めが足りなくても ①b に数える。

**② 送られない時刻**
- T・T＋1分・T＋3分が、すべて `isPossiblyClosed` の中にある。
- `isPossiblyClosed`: UTC で、金曜 21:00 以後、土曜、日曜 22:00 より前。

**③ 窓の穴**
- 開いている枠: その足の長さの枠のうち、②で送られない時刻でなく、GMO の休み（2）でもなく、5ペアのうち3ペア以上に足がある枠。
  - 枠は、格子の [a, a＋長さ)（a は長さの倍数）。
  - ② と休みは、枠の始まり a で見る。a・a＋1分・a＋3分がすべて isPossiblyClosed の中なら ② の時刻。a が休み（2）の時刻なら休み。
  - 格子の枠では、これは「枠がまるごと ② の時刻か休みの中にある」と同じ。例: 日曜 21:45 の15分足の枠と、12/25 20:00 の1時間足の枠は開いていない。12/24 20:45 の15分足の枠は、休みではない。
- 穴: そのペアに足が無い開いている枠が、時計の上で隣り合って続く所。長さが15分足で2枠以上、1時間足で1枠以上のもの。
  - 間に開いていない枠があれば、そこで切れる（開いていない枠を飛ばして、つながない）。
- 外す合図: 穴の枠 [a, a＋長さ) のどれかが、[s_{i−9}, T_i) と長さのある重なりを持つもの（a < T_i かつ a＋長さ > s_{i−9}）。
  - 端で触れるだけ（a ＝ T_i、または a＋長さ ＝ s_{i−9}）は外さない。T_i に始まる穴は、T より後の足の有無で決まるため。
  - 足 i があるので、窓と重なる穴は s_i 以前に終わる。穴の長さも、T_i までに確定した足だけで決まる。

**④ 週末・休みをまたぐ**
- [T, X)（T を含み、X を含まない）が、金曜 21:00 UTC の時刻を含む。
  - つまり、t_F ＝ T 以上で最初の金曜 21:00 UTC として、X > t_F。X ＝ t_F は外さない。T ＝ t_F は外す。
  - T が金曜 21:00 より後の週末（② の時刻）なら、t_F は次の週の金曜で、この金曜の決まりには当たらない。この T は、先に ② に当たる。
- または、[T, X) が GMO の休み（2）の時刻（12/25・1/1 の、前日 21:00 以上、その日 21:00 未満の t）を1つでも含む。
  - 休みの時刻は [前日 21:00, その日 21:00) なので、これは T < その日 21:00 かつ X > 前日 21:00 と同じ。X ＝ 前日 21:00 ちょうど、T ＝ その日 21:00 ちょうどは外さない。
  - 理由: 取引の足は [T, X) の中にある（入る足の始まり ≧ T、出る足の確定 ≦ X）。金曜の「越える」と同じ形にそろえる。
- 8.8 の Δ_late では、④を、X を X＋15分 に替えた同じ形で当てる（[T, X＋15分) が、金曜 21:00 UTC か休みの時刻を含めば外す）。
- 週の止まりは、②と同じ金曜 21:00 UTC の1つの時計にそろえる（反証 A9）。
  - 理由: GMO の夏の金曜の15分足は 20:45 の足まである（trend-data.ts の注記。GMO の生の足で、この研究では確かめていない）。
  - 冬の 21:00〜22:00 の1時間は、使わない側に倒す。

**⑤ 週明けと休み明け**
- T が、日曜 21:00 UTC より後で、月曜 00:00 UTC 以前。
- または、GMO の休みの日の終わり（21:00 UTC）より後で、次の 00:00 UTC 以前。
- 理由: 週末の窓で、交差・ROC・TR の拡大などが出やすくなる（反証 C9）。1週の約2時間分。

**⑥ スプレッドの広い枠**（22 の問3 が (a) の時だけ）
- 入りの枠、または出口の枠が、avoid＝yes になっている。
  - 入りの枠: そのペア、季節 season(T)、slotOf(T)。
  - 出口の枠: そのペア、季節 season(X−1分)、slotOf(X−1分)。
- 見る表は、`research/ledger/spread-hours-h1.csv`。
  - 表は、5ペア × 季節2 × 枠96 の960行を、1回ずつ持つ（`spreadhours-lib.ts` の parseSpreadHours と同じ読み方）。
  - 行が足りない・同じ行が2回ある・見出しが違う・5ペアのほかのペアの行がある表は、読む所で止まる。行の無い枠を avoid＝no と読むことはしない。
  - だから、表を作る時は、5ペアの行だけを書く。
- 季節・枠の決め方は `spreadhours-lib.ts` と同じ:
  - 季節は NY の夏と冬。
  - 枠は UTC の15分。
- 表の作り（反証 C2）:
  - `spreadhours.ts` と同じ作りで、1分足を 2024-01-01 00:00 UTC 以上、2025-05-16 21:00 UTC 未満（前半だけ）から作る。
  - 避ける枠は、中央値 ≧ max(3 × 全体の中央値, 1.0 pip) で、本数が1,000以上の枠。
  - 段0の前に作り、sha256 を定数にする。
  - 今の `spread-hours.csv`（2024〜2026、後半を含む）は使わない。

**外す理由の後で数えるもの**

- 層に目つぶりが無い合図:
  - 取引が作れない合図（次の行）を、先に外して数える。
  - その後は、作りの上で0件になる。数えた合図の足と向きは、同じ層の目つぶりの行でもあるため（8.1）。Δ_late と週ずらしでも同じ。
  - 0件でなければ、プログラムの誤りとして止まる。
- 取引が作れない合図（7 の入りの足が無い）: 外して、数を出す。T より後の足で決まるので、試しを落とす理由にはしない。

## 7. 取引（入りと出）

- **入る足 j**: 始まりが T 以上、X 未満の最初の足。無ければ「取引が作れない」。
- **入りの値段**: 買いは Ao[j]、売りは Bo[j]。
- **出る足 x**:
  - 確定がちょうど X の足。
  - それが無ければ、始まりが s_j 以上で、確定が X 以前の最後の足（数を出す）。
- **出の値段**: 買いは Bc[x]、売りは Ac[x]。
- **N ＝ 8**（15分足で2時間、1時間足で8時間）。
  - 理由:
    - 合図の作りの本数（7〜55本）の3分の1から半分くらい先を見る長さにした。
    - 持つ長さは本数で決めるとどの足でもそろう（§8.8）。
    - 1時間足でも1日以内に収まる。
  - N は1つだけ。結果を見て変えない。12本にするかは、オーナーに聞く（22 の問1）。
- **1件ごとの値**:
  - m ＝ d × (Pc[x] − Po[j])（点）。h ＝ m の符号（+1・0・−1）。
  - PL（点）:
    - 買いは Bc[x] − Ao[j]、売りは Bo[j] − Ac[x]。
    - 1回あたりの pips は PL ÷ 10。
  - W ＝ 1（PL > 0 の時）、でなければ 0。
- **損切り・利確**: 主の測り方では使わない。だから、同じ足で両方に届いた時の扱いは要らない。
- **重なる取引**: 前の取引の間に出た合図も、1件ずつ数える。
  - 説明として、同じペア・同じ向きで、残した前の取引の X より前に出た合図を除いた「重ならない版」の Δ と PL も、点だけ出す（見る合図と除き方は 21.5）。

## 8. 物差し

### 8.1 目つぶりの表

- 各ペア・各半分で、①〜⑥を通った足すべてについて、買いと売りの両方を、7 と同じ入り方・出方で作る。
  - 取引が作れない足（7 の入りの足が無い）は、表に入れず、数を出す。入りと出の足は買いと売りで同じなので、両方とも作れるか、両方とも作れない。
- 売りの h は、同じ足の買いの h の符号を変えたもの。
- 売りの PL は、売りの式で別に出す。
- どの試しの取引も、この表のどれか1つの足・向きの取引と同じになる。段ごとに、その段の半分の表を1回だけ作り、試しはそこから引く。

### 8.2 層

- 層 s ＝ ペア × 向き × T の UTC の時（0〜23）× 季節の組。
- n_s はその層の、取引が作れた数えた合図の数（6 の最後で外した、取引が作れない合図は入れない）。N ＝ Σ n_s。
- m_s はその層の目つぶりの数、B_s はその層の目つぶりの h÷2 の平均。

### 8.3 Δ（向きの当たり。ポイント）

- Δ ＝ 100 × Σ_s (n_s ÷ N) × (その層の合図の h÷2 の平均 − B_s)。
- 鏡との差: a ＝ 100 × (h の平均) ÷ 2。
  - 同点が無ければ「当たった割合 − 50%」と同じ。
  - 中値で測るので、鏡は −h になる。
  - そろえない数字として、いつも並べる。
- 向きの当たり（50 ＋ a）を「勝率」とは呼ばない（反証 B4）。勝率は W の割合だけ。

### 8.4 PL（損益。pips）

- PL の平均 ＝ 取引が作れた数えた合図すべての PL ÷ 10 の平均。
- 説明として出すもの:
  - 目つぶりの PL を層の重み n_s ÷ N で足したもの。

### 8.5 幅（95%）と p

**影響関数**（§8.113 8 と同じ作り。決めるのは下の式。§8.113 8 と違う所があれば、この文に従う。TS も同じ）
- 合図 i（層 s）: (d_i − Δ') ÷ N。d_i ＝ h_i÷2 − B_s、Δ' ＝ Δ÷100。
- 目つぶりの足 j（層 s）: −(n_s ÷ N) × (h_j÷2 − B_s) ÷ m_s。
- PL: (PL_i ÷ 10 − PL の平均) ÷ N（pips。PL_i は 7 の点〈整数〉、PL の平均は 8.4 の pips）。
- a（10 の「a と幅」）: (h_i ÷ 2 − a′) ÷ N。a′ ＝ a ÷ 100。目つぶりの項は無い（a は目つぶりを引かない）。
  - a の SE の候補と幅は、Δ と同じ作り（週ずらしは a_k）。κ はかけない。a の p は使わない。

**塊ごとの標準誤差**
- 塊は、週（wk(T)）と4週。
  - 4週の塊は 1 の floor((wk(T) − w0) ÷ 4)。`money-stats.ts` の clustered など、floor(週 ÷ 4) で区切る関数は使わない（区切りが1週ずれる）。
- 塊ごとに影響関数を足して S_g とし、SE ＝ √(C ÷ (C−1) × Σ S_g²) とする（Δ と a は ×100。足す順は 21.5）。
- C は、その試しの合図か、その半分の目つぶりの表の行（どの層の行でもよい。影響が0の行も数える）がある塊の数。Δ・a・PL で同じ C を使う。Δ_late では、遅れた目つぶりの表で数える。
- 4週の塊の C（C_4週。上と同じ数え方）が10に足りなければ、4週の候補を使わない。週と週ずらしの2つから選ぶ（8.6 の D_F の幅は、週だけ）。

**週ずらし**
- その半分の目つぶりの表に足がある週を古い順に並べる（数 W_h）。Δ_late では、遅れた目つぶりの表で数える（ずらした先の取引も、その表から引く。21.5）。
- ずらすのは、その値に入った合図だけ（21.5）。その値から外した合図は、ずらさない。
  - Δ（と PL・a）: 取引が作れて、層に目つぶりがある、数えた合図。
  - Δ_late: Δ_late に入った合図（8.8 で外した合図は入らない）。
- その合図の並びを、まるごと k 週（k ＝ 1〜W_h−1）後ろへ、半分の中で輪のようにずらす。週の中の曜日・時刻はそのまま。
  - k 週は、並べた週の中で k 個後ろの週のこと（暦の k 週ではない）。最後の週の後ろは、最初の週に戻る。
  - 週 w の合図は、並べた週で k 個後ろの週 w′ に移す。T′ ＝ T ＋ (w′ − w) × 1週。
- ずらした先の足が目つぶりの表に無い合図は、その k では落とす。
- 層は、ずらした先の T で決め直す。
- 取引は目つぶりの表から引き、Δ_k と PL_k を出す（a の幅のために a_k も出す）。
- 残った合図が0件の k は使わず、その数を出す。使う k の数を K とする。
- Δ_k の K 個の標準偏差を、Δ の SD_shift とする。PL_k と a_k も同じ。どれも2回に分けて計算し、K − 1 で割る。
- K < 2 なら、SD_shift は無し（その候補は t が無い）。

**SE の候補**
- (週, C_週 − 1)、(4週, C_4週 − 1)、(SD_shift, C_週 − 1) の3つ。

**どの候補を使うか**（反証 C10）
- 95% の幅と LB: t(0.975, 自由度) × SE が一番広い候補を使う。
- p: 片側の p ＝ 1 − T(Δ ÷ SE, 自由度) が一番大きい候補を使う。
  - 幅でも p でも、同じなら、週・4週・週ずらしの順（数は同じで、選んだ候補の名前だけが変わる）。
- 95% 以外の幅（11 の同時の下の端、12 の片側95%）も、その水準の t × SE が一番広い候補を使う。
- t の分布は `money-stats.ts` の tQuantile と同じ作り:
  - U(x, ν) ＝ ½ × I_{ν÷(ν＋x×x)}(ν÷2, ½)。x ≧ 0 の上の裾（t が x より大きい確率）。I は正則化した不完全ベータ関数。
  - T(x, ν) は、x ≧ 0 で 1 − U(x, ν)、x < 0 で U(−x, ν)。
  - 分位 t(q, ν)（0.5 < q < 1、ν ≧ 1）: 下 ＝ 0、上 ＝ 1 から始める。T(上) < q の間は、上を2倍にする。次に、上 − 下 > 1e−12 の間（200回まで）、真ん中 m で T(m) < q なら下 ＝ m、でなければ上 ＝ m とする。答えは (下 ＋ 上) ÷ 2。
  - 片側の p ＝ 1 − T(x, ν)（x ＝ 値 ÷ SE）。x ≧ 0 なら U(x, ν) をそのまま使い、1 から T を引かない（引くと、小さい p が 0 になり、並べ方が変わる）。x < 0 なら 1 − U(−x, ν)。
  - TS の分位は tQuantile を呼ぶ。TS の U は、`money-stats.ts` に U(x, ν) を返す関数を export で足して呼ぶ（中は今の ibeta をそのまま呼ぶ。今の関数は変えない。写さない。ibeta・tCdf は今 export されていない）。
  - Python は、U の相対誤差が 1e−12 より小さい作りなら、何でもよい（例: 閉じた式を Decimal で）。
  - tQuantile の分位は、正確な値と最後の桁が違う（二分法を幅 1e−12 で止めるため。手の例の26個で測った差は 4.2e−13 未満）。照らし方は 17.2（分位とそれを使う値は 1e−9 以内、p は相対 1e−9 以内）。
  - 分位か p を使う判断で、比べる2つの値の差が 1e−9 未満のもの（p としきい値、幅の端と 0、LB や p の並び）は、分かれてよい（17.2 の許す違い。分かれた数と場所を出す）。
    - ただし、段1で選ぶ試し、段2の Holm で通る試しと判定、段3の判定のどれかが分かれたら、先へ進まずに止める。2つの値と場所をオーナーに伝える。
    - それ以外は、TS の値で進む。
- C < 2・N ＝ 0・SE ＝ 0 の候補は、t が無い（週ずらしは K < 2 も）。
- 使う候補のどれか1つでも t が無ければ、その値（Δ か PL）は t が無いとする。p ＝ 1 で、幅と LB は無し。
- 10 の「t が作れて」は、Δ の t があること。
- 0 との比べは、|x| < 1e−12 を 0 とする。

## 14. 作り物の値段

### 14.1 生成器（`research/lawsearch-gen.ts`。trend-data.ts の walk5 を広げた新しい関数。walk5 は変えない）

**値動き**
- 1分ごとの中値の動き。5分足を作り、`coarsen` で15分足・1時間足を作る。
- GMO の日のファイルの形で書き、本番と同じ `loadTf` で読み直す（analog の walkfiles と同じ道）。
- 始値: ドル円 110.000、ユーロ円 125.000、豪ドル円 80.000、ユーロドル 1.10000、豪ドル/ドル 0.70000。
- 1分の動きの大きさ:
  - 基本は、円のペア 1.0 pip、ドルのペア 0.6 pip。
  - これに UTC の時間帯の倍率を掛ける: 00〜06時 0.8、07〜15時 1.2、16〜20時 1.0、21〜23時 0.6。
  - さらに日のボラの倍率 exp(x_D) を掛ける。x_D ＝ 0.9 x_{D−1} ＋ 0.15 ε_D。5ペアで共通。
- 裾の太さ: 1分の動きは、自由度4の t 分布を √2 で割ったもの（分散1）。
  - t は、正規の z と χ²_4（正規4つの2乗の和）から z ÷ √(χ²_4 ÷ 4) で作る。
  - 正規は mulberry32 と Box–Muller（walk5 と同じ形）。
- ペアどうしのつながり（反証 C11。実際の相関の値ではなく、決めた値。データは読んでいない）:
  - 共通の動き U（ドル）と Y（円）を作る。
  - 各ペアの1分の動き:
    - ドル円 ＝ 0.5U − 0.5Y ＋ √0.5 × 自分
    - ユーロ円・豪ドル円 ＝ −0.6Y ＋ 0.8 × 自分
    - ユーロドル・豪ドル/ドル ＝ −0.6U ＋ 0.8 × 自分

**スプレッド**
- `spread-hours-h1.csv` の、そのペア・季節・枠の中央値。
- 15分の枠ごとに種から作った乱数で、1割の枠だけ p90 にする。
- 刻みに丸め（ちょうど半分は上）、Bid は中値からスプレッドの半分を刻みで切り下げた分だけ下、Ask は Bid ＋ スプレッド。

**時刻**
- `walkOpen`: 日曜 22:00 UTC〜金曜 21:00 UTC（夏）／22:00 UTC（冬）。12/25 と 1/1 は休み。
- 休みの後は、15分の動き3つ分だけ跳ぶ（walk5 と同じ）。
- 期間は S0〜END。

**決めた後は変えない**: この生成器は、試しの種 901〜920 で効果の強さを決める前に決め、後から変えない。

## 21.5 読みを1つに決めた所（付録 A を作る時に見つかったもの。2026-11-04、データを読む前）
